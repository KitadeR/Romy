# Romyの中継API

APIキーをアプリに含めず、公開情報の確認・一言の解釈と費用制限を担当します。

## 開発・検証

```sh
npm ci
npm test
npm run typecheck
npm run db:local
npm run dev
```

`PERPLEXITY_API_KEY` はGit管理外の `.dev.vars` に設定します。アプリ用の `APP_TOKEN` は公開環境のSecretで管理し、値をコミットしません。

アプリは実機・Simulatorともに、通常は `Romy/Config/Relay.plist` の公開中継へ接続します。上記の `npm run dev` へ接続して開発する場合は、Debug版Simulatorの起動引数に `-romy-relay-local` を指定してください。このときだけ `http://localhost:8787` を使い、公開中継用のアプリトークンは送りません。実機・Release版ではこの引数は無効です。

## 検索と読み取り

宿の荷物預かりと営業時間は、PerplexityのSearch APIで抜粋を集め、Workers AI（`@cf/google/gemma-4-26b-a4b-it`、`wrangler.toml` の `AI` バインディング）が読み取ります。宿名・店名を含まない抜粋は読ませず、同じ宿かどうかと公式かどうかの最終判断はコードで行います。検索は1回0.005ドルとして日次上限に数え、読み取りはWorkers AIの無料枠（1日1万Neuron）を使います。PerplexityのAgent APIは有料クレジットが必要なため使っていません（一言の解釈の入口だけ旧来のAgent APIのまま残り、アプリは端末内で解釈するため呼びません）。

## 判定の評価

`eval/` は保存した検索結果で宿の荷物預かりの判定を採点します。正解は `eval/luggage/expected.json`（各宿の公式ページで確認）。検索結果 `eval/luggage/search/` は他社の抜粋を含むためGit管理外です。

```sh
npx wrangler dev -c eval/wrangler.toml --port 8797   # 別のターミナルで
node eval/score.mjs 3
```

営業時間の評価は [eval/hours/README.md](eval/hours/README.md) を参照してください。公開カフェ12件の検索結果を保存し、本番と同じ読み取り・判定で比較できます。初回の結果と調査点は [2026-11-18の記録](eval/hours/baseline-2026-11-18.md) にあります。

## 営業時間の時刻照合

営業時間の数値はAIに計算させません。検索抜粋にある営業区間とLOをコードで抽出し、AIには対象店舗・対象日に当てはまる営業区間の候補IDだけを選ばせます。候補IDは抜粋の該当箇所に埋め込み、IDと原文の時刻だけの短い一覧を添えます（候補ごとに前後の文を送ると入力が抜粋の3〜5倍に膨らんだため）。LOはAIに選ばせず、同じページの同じ区間の後ろ200文字以内にある原文とコードで対応付けてから分数に変換します。原文にない候補IDや、旧形式の生成された数値だけの回答は採用しません。候補・原文・抜粋はアプリへのレスポンスや本番ログに含めません。

全角、午前・午後、AM/PM、深夜営業（翌2時／26時）、前日からの明記された営業、24時間営業を扱います。「翌」「26時」の明記がない日付またぎは、閉店が6時までの場合だけ認めます。同じ営業区間はまとめ、出典間でLOが食い違う場合や区間が重なる場合は矛盾として未確認にします。同じ区間の案内に複数のLOがある場合は対象メニューを推測せず、LOを不明として扱います。候補を抽出できない表記は推測で補いません。

支店の一覧ページで別支店の時間を選ばないよう、ページのタイトルに正式名があるか、その営業時間の区切り（一つ前の営業時間の後ろから最大400文字前まで）に店名・末尾の支店名・依頼された住所のどれかがある候補だけを採用します。AIが返す住所は入力をそのまま写すことが多く、店舗の確認の根拠にはしていません。

休業は、公式ページの原文の引用で確かめます。年つきの日付（2026/11/8・2026年11月8日・2026-11-08・'26/11/8）が対象日と一致するか、年のない日付に書かれた曜日が対象日と一致し、その日付に休業と書かれている場合に採用します。「定休日：水曜日」のように対象日の曜日が書かれた定休日も休業とします。祝日・第何週・不定休に触れる案内、対象日が営業とも読める案内は未確認にします。分からない場合は休業とも営業ともせず、未確認にします。

矛盾（`conflicting`）は、公式ページ同士で対象日の営業時間・休業が食い違うときだけとし、確認できないことや、食べログ・口コミ・地図など公式でないページとの違いは矛盾にしません。ランチタイム・モーニングなど営業時間の中の一部の時間帯は選ばせません。個人ブログや地図・まとめ記事は公式でないサイトの一覧（`src/official.ts`）に含め、AIが公式と答えても公式にしません（[2026-11-19の見直し](eval/hours/conflict-2026-11-19.md)）。

店舗・対象日の選択と公式ページの判定・公式同士の矛盾の判定は引き続きAIに依存します。臨時変更がないことまでは保証しません。

古い誤読結果を返さないよう、営業時間のキャッシュキーを `hours:evidence-v1:` に分けています。DB移行は不要で、旧キャッシュは既存の有効期限で消えます。反映直後は既存の回数・費用制限の範囲で再確認します。アプリ向けの営業区間は従来と同じ分数形式です。評価の結果は [eval/hours/holdout-2026-11-19.md](eval/hours/holdout-2026-11-19.md) にあります。

## 営業時間の診断

`/v1/scene` の既存レスポンスに、任意の `diagnostic`（`code`、キャッシュ利用の有無、検索／読取対象の件数）を追加しています。古いアプリは追加項目を無視できます。判定コードは営業時間キャッシュにも保持し、古い未確認キャッシュの理由は `cached_unknown` とします。DB移行は不要です。

CloudflareのWorkerログでは `event: "hours_result"` を確認します。理由は最初に拒否された条件であり、唯一の原因とは限りません。

| コード | 意味 |
| --- | --- |
| `device_limit` / `budget_limit` / `session_limit` | 端末日次／全体費用／セッションの上限で未実行 |
| `api_unconfigured` | 中継に検索APIキーが未設定 |
| `search_failed` / `reader_failed` | 検索／AI読み取りで失敗 |
| `search_empty` / `place_not_matched` | 検索結果なし／店名フィルター通過なし |
| `reader_empty` / `reader_invalid_json` | AIの回答なし／JSONとして読めない |
| `name_mismatch` / `address_mismatch` / `date_mismatch` | 店名／住所／対象日の照合失敗 |
| `conflicting` / `no_official_source` | 情報の矛盾／採用できる公式出典なし |
| `invalid_hours` / `no_hours` | 不正な時刻／営業区間の根拠不足 |
| `confirmed` | 既存の公式確認条件を通過。正確性は別途評価する |
| `internal_error` / `cached_unknown` | その他の処理失敗／旧キャッシュで理由不明 |

アプリ側はXcodeのログでカテゴリ `Hours` を確認できます。サーバーのコードに加え、`client_session_limit`（アプリの3回上限）、`missing_address`、`missing_config`、`transport_failed`、`http_rejected`（HTTP状態も記録）、`response_invalid` を記録します。診断に対応していないサーバーの応答は `unknown` です。

本番ログは固定の理由・件数・時間だけです。店名、住所、対象日、URL、端末ID、セッションID、認証情報、AI応答本文は出しません。アプリも固定コードだけをdebugログに出し、画面には表示しません。公開環境で新しい診断を取得するにはWorkerの反映と新しいアプリのビルドが必要です。

## Romy Now

`POST /v1/scene` に `session`（UUID）と次のいずれかを渡します。既存の `X-Romy-Device` / `X-Romy-Token` による認証・上限を共用します。

- `operation: "interpret"`：`text`（300文字まで）から食べ物・店舗種別、徒歩上限、休憩時間、全体の時間を抽出。未対応の希望は `unhandled` に返す。
- `operation: "hours"`：`name`, `address`, `date`（現地日付）, `timeZone` で営業時間を確認。別支店・別日・出典不一致・矛盾は `unknown` に返す。

同じセッションの解釈は1回、検索は宿の荷物預かりを含めて3回までです。既存アプリとの互換性のため `/v1/check` の `session` は省略できます。新しいRomy Nowは必ず送ります。検索の端末日次上限・全体の費用上限は `wrangler.toml` の既存値を使います。セッションIDと端末IDは本人認証の代わりにはなりません。

一言は共有DBへ保存せず、内容をログにも残しません。営業時間は店舗・対象日・タイムゾーンごとに、公式確認なら1時間、未確認なら5分間キャッシュします。営業区間は現地日の0時からの分数で、翌日2時は1560です。到着・出発・ラストオーダーとの比較はアプリが行います。空席や臨時変更は保証しません。

本番反映時は `0002_scene_sessions.sql` をD1へ適用してからWorkerを反映します。既存テーブルのデータ削除やアプリの秘密値の変更は不要です。

API仕様は [Perplexity Search API](https://docs.perplexity.ai/getting-started/pricing) と [Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/) を参照しています。
