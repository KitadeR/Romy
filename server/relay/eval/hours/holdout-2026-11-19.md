# 確認用の店での評価と、判定の見直し（2026-11-19）

[時刻の原文照合（2026-11-18）](time-validation-2026-11-18.md) の比較は、方式を調整したのと同じ12件で測ったものです。2026-11-19に判定を見直し、調整に使わない確認用の8件（`holdout.json`）で、修正前・Codex版・修正版を比べました。

## 判定の見直し

- **休業日:** 日付を部分一致で探していたため、「2026/11/18は休業」の原文で11/1も休業と確定していました。日付を数値で読み、年が一致する場合か、年がなくても書かれた曜日が対象日と一致する場合だけ採用します。「定休日：水曜日」のように対象日の曜日が書かれた定休日は休業とし、祝日・第何週・不定休に触れる案内や対象日そのものの案内がある場合は未確認にします。
- **支店の一覧:** 公式の一覧は「見出し → 説明 → 住所 → 営業時間 → 次の店の見出し」の順で、営業時間の前後100文字では自店の見出しが届かず、次の店の見出しが入っていました。その営業時間の区切り（一つ前の営業時間の後ろから最大400文字前まで）に店名・支店名・依頼された住所のどれかを求めます。
- **AIへの入力:** 候補ごとに前後100文字を送っていたため、入力が抜粋の3〜5倍に膨らんでいました（小川珈琲 本店で抜粋1,816文字に約9,700文字を追加）。候補idを抜粋に埋め込み、idと原文の時刻だけの短い一覧を添えます。埋め込みだけではAIが候補を見落とし、空のidを返しました。
- **住所:** AIが返す住所は入力をそのまま写すことが多く（12件×3回で33回中32回）、照合の根拠になりません。店舗の確認は上の区切りの照合で補います。表記ゆれへの対応はIssue #12で継続します。
- **その他:** 「Polo」など英単語の一部をLOとして拾わない。「翌」「26時」の明記がない日付またぎは閉店6時までに限る。

この見直しは同じ12件の結果を見ながら行いました。12件×3回では、通常案内と一致18、不一致0、JSONとして読めない回答0、読み取り・判定の中央値約5.6秒・p95約12.4秒でした（Codex版は一致17、JSON崩れ2、p95約24.7秒）。調整に使った集合なので、改善の根拠には下の確認用の店を使います。

## 読み方と残る課題

- 誤った確認済みは5→0になりました。一方で確認できた件数は6→3に減り、修正前に正しく休業と確認できていた天下一品の臨時休業も未確認になりました。
- 未確認の主な原因は、AIが `conflicting=true`（出典が食い違う）と答えることと、検索で公式ページを取得できないことです（前田珈琲の2店舗はナビタイム・食べログだけが取れた）。修正版ではAIがナビタイムを公式と判定した回もありました。矛盾の判定と公式ページの取得は、この確認用の店を使わずに別途改善し、改善後に同じ確認用の店で測ります。
- 休業日の判定の見直しは、AIが休業と答えて矛盾なしとした場合にだけ働きます。今回の確認用の店ではその前の段階で止まったため、休業日の照合そのものは単体テストでしか確かめられていません。
- 東華菜館の「12/1（火）、8(火）…」のような並べ書きは、日付ごとに休業の語がないため休業とは読みません（未確認になる）。
- 8件・各3回・Gemma 4の揺れを含む少数の計測です。全店舗の成功率や対象日の正解率を示すものではありません。

生の回答と抜粋はGit管理外の `results/holdout-before.json`、`results/holdout-codex.json`、`results/holdout-after.json`、`search/` にあります。
