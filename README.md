# Romy（ロミー）

**旅をもっと楽しく、もっと笑顔に。**

旅行の計画・準備から旅行中の行動までを支えるiOSアプリです。Romy Nowでは、現在地・そのときの状態・旅程から過ごし方を比較し、変更内容を確認して同じ旅程へ反映できます。

## 起動・確認手順

現行構成をもとにした確認手順です。提出するコミットでの最終確認はこれから行います。

1. macOS・Xcode・iOSの対応環境を用意し、ソースコード一式に含まれる`Romy.xcodeproj`をXcodeで開きます。SchemeはRomy、実行先は対応するiPhone Simulatorを選びます。実機を使う場合は自分の署名設定を確認します。

2. Build／Runして起動します。旅行作成・旅程管理・Romy Nowの案の比較や反映などの基本機能は、中継サーバーを起動せずに確認できます。場所検索・経路取得には通信が必要で、現在地を使う場合は利用許可が必要です。

3. 検索AIによる宿の情報確認を試す場合は、`server/relay`で`npm ci`を実行し、`.dev.vars.example`を`.dev.vars`へコピーして、自分のPerplexity APIキーを設定します。`npm run db:local`でローカルD1を準備し、`npm run dev`で中継サーバーを起動します。キーはアプリ本体やGit管理対象へ含めません。

4. シミュレーターではMac上の`http://localhost:8787`へ接続します。iPhone実機は、`server/relay/Relay.plist.example`を参考に作成した`Romy/Config/Relay.plist`から、公開中継のURLとアプリ用トークンを読み込みます。この設定ファイルはGit管理対象外です。設定がない場合は、新たなAIの確認結果を取得できません。提出時の設定の受け渡し方法は確定後に追記します。

5. 旅行を作成し、行き先・日付・旅行名を設定します。予定と宿を追加し、日別の地図・旅程・詳細や、ホーム・準備タブの表示を確認します。

6. Romy Nowの代表的な設定例・操作・確認事項は、下の「Romy Nowの操作例（手順の下書き）」にまとめています。

7. 状態と疲れの強さを選び、案の一覧・要約・変更プレビューを確認します。確定前に旅程が変わらないこと、確定後の追加・未定への移動、通知からの「元に戻す」を確認します。

8. 現在地なし、次の固定予定や場所の不足、候補なし、通信・経路取得失敗、検索後の旅程変更も確認します。再起動後の保存・再開も確認します。

9. AIの情報確認は、場所を指定したホテル等の宿泊予定を新しく追加し、説明シートで「わかった」を選んでから試します。旅行当日の宿を用意して「荷物が重い」からRomy Nowを開き、確認中から結果への表示、出典・確認日を確認します。AIの結果が取得できない場合も、確認できない情報は未確認として扱います。


### Romy Nowの操作例（手順の下書き）

場面：午後の観光中、歩き疲れて荷物も重い。宿のチェックインや次の予約まで、今からどう過ごすか考えたい。以下の設定例を通した一連の検証は未実施です。提出版で時刻・画面の文言・結果を確認して確定します。

#### 用意する条件

- 確認開始時刻をTとし、同じ日の約3時間先まで予定を置ける日中に試します。Tが14:00なら、宿は15:00から、次の固定予定は17:00です。別の時刻には時差を保って設定し直します。

- 京都を行き先に、今日から1泊の確認用旅行を新規作成します。京都駅の予定をTの約30分前開始・滞在約60分で追加し、ホームで京都駅が「今の予定」になることを確かめます。この時刻設定での表示も提出版で最終確認します。

- 場所検索から宿（例：ホテルグランヴィア京都）を追加し、チェックイン可能時刻をTの約1時間後に設定します。次の固定予定（例：松葉 本店）は開始をTの約3時間後に固定します。順序は京都駅→宿→次の固定予定です。すべてテスト用の予定です。

- Simulatorの位置を京都駅付近に設定します。場所検索と徒歩経路取得には通信が必要です。実機では実際の現在地に合わせて場所を置き換え、別の条件として確認します。固定予定はこの代表例の条件であり、すべての利用に必須という意味ではありません。

#### 操作と確認したい動作

1. ホームの「いまどうする？」から開き、「疲れた」「荷物が重い」を選びます。疲れの強さは弱めに設定します。

2. 検索し、徒歩時間・休める時間・次の予定までの余裕を比較します。閲覧だけでは元の旅程が変わらないことを確認します。候補の名称・件数は検索条件によって変わります。

3. 案を選び、手順・時刻の目安と変更プレビューを確認します。追加される予定、未定へ移る予定、変更後の時刻を確定前に確認できることを確かめます。

4. 「この内容で旅程に入れる」で確定し、変更が旅程へ反映されることと、次の固定予定の時刻が保たれることを確認します。

5. 反映直後の通知（約5秒）の「元に戻す」を押し、追加した予定が消え、移動した予定の位置・日・滞在時間が変更前に戻ることを確認します。

#### 検索AIの情報確認を追加で試す場合

中継に接続せずに比較・反映・取り消しを試せます。荷物預かり情報も試す場合は、前述の中継設定を用意し、場所を指定した宿を新しく追加した際の説明シートで「わかった」を選びます。出典・確認日・未確認の表示を確認します。保存済みの結果があれば、確認中を経由しない場合もあります。公式案内が必ず見つかることや、当日の受付・空きを保証する確認ではありません。

#### 実行後に残す記録

提出コミット、端末とOS、実施日時、予定・位置の設定、表示された案と各操作の結果を記録します。候補が出ない場合は、通信・位置・今の予定・残り時間を確認します。固定予定なし、通信失敗、検索後の旅程変更、保存・再開は別ケースとして確認します。
